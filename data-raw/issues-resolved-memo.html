These cases have a clear diagnosis, but the fix is a modelling or naming decision that changes table or column names downstream, or it needs information that isn't available locally. Each is recorded as needs_input in the validation log. The 990-PF cases are waiting on one decision: when to merge the PF concordance.

1. Part III programs: one variable in five tables

Cases: R07 ×5, COLLISION ×5, V_POOLED_SCALE ×3 (F9_03_PROG_CODE, _DESC, _EXP, _GRANT, _REV).

v1 maps lines 4a, 4b, 4c, 4d (other) and the 990-EZ programs to the same five variable names. xpath_overrides.csv then sends each line's xpaths to its own table: F9-P03-T00-PROGRAM-ONE, -TWO, -THREE, F9-P03-T01-PROGRAMS-OTHER and F9-P03-T02-PROGRAMS-EZ. So one column name appears in five tables. The collisions are real in the sense that 4a and 4b hold different programs (TY2019: 96,251 filings fill both descriptions). They only become a problem if a parser pools by variable name.

  1. One programs table. Replace the five tables with one MANY table (for example F9-P03-T01-PROGRAMS) with a program column (4a/4b/4c/other/EZ). Each concept is one variable. This renames tables downstream, and the crosswalk carries v1 data across.
  2. Separate names per table. Keep the five tables and give each line its own variables (for example F9_03_PROG_4B_DESC). This renames columns downstream.
  3. Keep and document. Record an exception to R07 for Part III and evaluate collisions within each table. Nothing is renamed.

Recommendation: option 1 for v2.0, since it is a major version and the crosswalk exists for this purpose. Choose option 3 if downstream stability matters more for this release.

2. Schedule O table name

Cases: R06 ×4 (SO_00_EXPLANATION_TEXT, _FORM_LINE_REFERENCE, _IDENTIFIER, _RETURN_REFERENCE).

SO-T99-SUPPLEMENTAL-INFO is the only table without a part number, so its variable prefix SO_00 can't match it. Part SO-P00 already exists.

Recommendation: rename the table to SO-P00-T99-SUPPLEMENTAL-INFO in v2.0. Code that reads the table by name must follow, and the crosswalk records the move. Say yes and it is a one-step logged fix.

3. Lists of codes inside one-row tables

Cases: ONE_REPEATS ×15. These are elements that repeat on their own rather than as rows of a group:

  • states where the return is filed (F9-P06)
  • foreign financial-account countries (F9-P05)
  • 990-EZ foreign office countries (F9-P04)
  • special conditions (F9-P00)
  • Schedule G licensed states and gaming states
  1. Child tables. Add a MANY table per list, for example F9-P06-T01-STATES-RETURN-FILED. The F9-P00-T01 number is now taken by AFFILIATE-LISTING, so special conditions would need another number.
  2. List-valued fields. Keep each field in its one-row table and mark it as holding several values (a new variables.csv column such as multi_value). Parsers then join the values, for example CA;NY.

Recommendation: option 2. It keeps one row per filing for the tables most people use, and the flag is a small Phase 4 addition.

4. 501(c) type in TY2009

Cases: INCIDENCE_BREAK ×1 (F9_00_EXEMPT_STAT_501C_X).

In the 2009 schemas every filer used Organization501c with a type attribute, and there was no separate 501(c)(3) element. So for TY2009, F9_00_EXEMPT_STAT_501C_X includes 501(c)(3) organizations and F9_00_EXEMPT_STAT_501C3_X is empty. The fix needs attribute xpaths (the 501(c) type attribute) in the concordance and in the evidence, and the evidence builder does not read attributes.

Recommendation: document it in the variable description now, and add attribute-level mapping with the XSD metadata work (Phase 4).

5. An unidentified TY2012 checkbox

Cases: UNMAPPED ×1 (/Return/ReturnData/IRS990/OtherExplainInSchO).

It appears only in the 2012v2.0–3.0 schemas, in 1,580 filings, and every value is X. Its form line can't be identified without the 2012 XSD, which isn't available locally.

Recommendation: check the 2012 XSD, then map it or add it to the ignore list.

6. 990-PF: when to merge (Phase 5)

Cases: 1,884 deferred, including 34 errors.

issues.html points PF fixes at the v1 file F990-PF-FULL.CSV and asks for them after the PF merge, so the changes are logged. The fixes for the 34 errors are already worked out:

  • Balance sheet (Part II), 17 variables. End-of-year book value is pooled with fair market value (for example CashEOYAmt with CashEOYFMVAmt, and TotalAssetsEOYAmt with TotalAssetsEOYFMVAmt in all 114,559 filings). Fix: split the FMV column (c) into its own variables.
  • F9_02_PF_BSCSBOY / BSCSEOY. Capital stock (a net-asset line) is pooled with corporate stock (an investment). Fix: split them.
  • Part XVI-A analysis of income, 8 variables. Exclusion codes are pooled with exclusion amounts, and F9_16_PF_AIPANRIRNDFP also pools the related and unrelated columns. Fix: split by column, with codes as text.
  • Part IV capital gains. Adjusted basis is pooled with FMV as of 12/31/69, and gain/loss with gross sales price. Fix: split by column.
  • Part VIII / XV foreign addresses. City, country and postal code are pooled. Fix: split by field.
  • F9_08_PF_RATAEPRATAEP. A line number is pooled with its statement text. Fix: split them.
  • AF_13_PF_ELECTIDESCES. Two different elections are pooled (applied to prior year, and distribution from corpus). Fix: split them.

Recommendation: start Phase 5 next. The PF fixes can then be applied and logged in the same way as fixes 01–07.
